Documentación de Peak Auth

Peak Auth es un Proveedor de Identidad (IdP) centralizado y servidor de autorización Single Sign-On (SSO), diseñado para ser seguro, rápido y compatible con estándares modernos mediante OAuth 2.0 con PKCE, JWT asimétrico (RSA-256) y descubrimiento dinámico de claves vía JWKS.

JWT asimétrico (RSA-256) & JWKS

A diferencia de los esquemas tradicionales que comparten un secreto simétrico (HS256) entre todos los servidores, Peak Auth opera con criptografía asimétrica de clave pública y privada, con rotación multi-clave e identificación por kid:

  • Clave privada: Reside exclusivamente en Peak Auth. Se utiliza para firmar los tokens JWT cuando un usuario inicia sesión.
  • Descubrimiento JWKS (RFC 7517): Expuesto públicamente en /.well-known/jwks.json. Las aplicaciones satélite no necesitan gestionar archivos PEM manualmente; descargan las claves públicas automáticamente, las cachean en memoria y resuelven la clave adecuada según el kid del encabezado del token.
  • Rotación sin tiempo de inactividad (Grace Period): Soporta múltiples claves previas en verificación. La clave activa firma nuevos tokens, mientras que los tokens emitidos previamente se validan sin interrupción durante la ventana de gracia.
Seguridad y audiencia estricta Cada JWT emitido contiene el claim aud: [client_id]. Los SDKs y microservicios deben verificar que la audiencia coincida exactamente con el Client ID de la app para evitar la reutilización no autorizada de tokens entre distintos clientes.

Flujo OAuth 2.0 con PKCE & SSO

El flujo estándar recomendado para aplicaciones web (SPAs), móviles y backends es el Authorization Code Flow con PKCE (Proof Key for Code Exchange):

  1. Inicio de autorización: La app cliente redirige al usuario a /oauth/authorize incluyendo client_id, redirect_uri, code_challenge (S256) y state.
  2. Sesión SSO o autenticación: Peak Auth verifica si existe una sesión activa compartida (peak_session). Si no existe, muestra el portal de inicio de sesión con soporte MFA (TOTP / WebAuthn). Si la política de la aplicación exige MFA y el usuario aún no lo configuró, se le guía a completarlo.
  3. Redirección con código: Peak Auth genera un código de autorización temporal de un solo uso (válido por 5 minutos) y redirige de vuelta a la app: https://tu-app.com/callback?code=...&state=....
  4. Intercambio de token: El backend o cliente seguro intercambia el código en POST /oauth/token enviando el code_verifier original.
  5. Emisión de tokens: Peak Auth responde con el Access Token firmado (RS256) y un Refresh Token rotativo.

OAuth 2.0 Client Credentials Grant (M2M)

Diseñado para comunicación Machine-to-Machine (M2M) entre microservicios, daemons, workers y servicios backend que operan sin intervención humana directa (RFC 6749).

El microservicio se autentica contra POST /oauth/token enviando su client_id y client_secret (vía cabecera HTTP Basic Auth o cuerpo JSON) con grant_type: "client_credentials". Peak Auth emite un Access Token JWT (RS256) sin refresh token, garantizando credenciales efímeras y seguras.

Identity Brokering (Social Login)

Peak Auth actúa como intermediario central de federación de identidades externas:

  • Proveedores soportados: Google y GitHub.
  • Vinculación automática: Si el usuario ya posee una cuenta local con el mismo correo verificado, se asocia su identidad federada de forma segura mediante UserIdentity.
  • Flujo sin fricción: Los usuarios pueden iniciar sesión con un clic desde el portal central o desde el flujo SSO de cualquier aplicación cliente.

Almacenamiento de archivos y perfiles

Peak Auth incluye un subsistema de almacenamiento desacoplado mediante la interfaz StorageService:

  • Disco local (STORAGE_DRIVER=local): Almacena avatares y archivos subidos en el sistema de archivos local (web/static/uploads/), ideal para entornos locales o despliegues ligeros.
  • Cloudflare R2 / AWS S3 (STORAGE_DRIVER=s3): Compatible con buckets S3 y Cloudflare R2 sin costo de egreso, configurables mediante variables de entorno (R2_ACCOUNT_ID, R2_BUCKET, R2_ACCESS_KEY_ID, R2_SECRET_ACCESS_KEY, R2_PUBLIC_URL).

SDKs oficiales

Peak Auth provee librerías oficiales livianas con verificación offline, auto-descubrimiento JWKS con caching en memoria y middlewares listos para producción:

TypeScript / Node.js

Compatible con Express, Next.js y cualquier entorno de ejecución Node.js / Bun moderno.

npm install @brunotarditi/peak-auth

Go (Golang)

Librería nativa con soporte para net/http y subpaquete para gin.

go get github.com/brunotarditi/peak-auth/sdk/go

Kotlin / Android / JVM

Librería nativa en Kotlin con corrutinas para aplicaciones Android y servidores backend JVM (Ktor, Spring).

implementation("io.peakauth:peak-auth-kotlin:0.1.0")
