Documentación de Peak Auth

Peak Auth es un Proveedor de Identidad (IdP) centralizado y servidor de autorización Single Sign-On (SSO), diseñado para ser seguro, rápido y compatible con estándares modernos mediante OAuth 2.0 con PKCE, JWT Asimétrico (RSA-256) y descubrimiento dinámico de claves vía JWKS.

JWT Asimétrico (RSA-256) & JWKS

A diferencia de los esquemas tradicionales que comparten un secreto simétrico (HS256) entre todos los servidores, Peak Auth opera con criptografía asimétrica de clave pública y privada, con rotación multi-clave e identificación por kid:

  • Clave Privada: Reside exclusivamente en Peak Auth. Se utiliza para firmar los tokens JWT cuando un usuario inicia sesión.
  • Descubrimiento JWKS (RFC 7517): Expuesto públicamente en /.well-known/jwks.json. Las aplicaciones satélite no necesitan gestionar archivos PEM manualmente; descargan las claves públicas automáticamente, las cachean en memoria y resuelven la clave adecuada según el kid del header del token.
  • Rotación sin Downtime (Grace Period): Soporta múltiples claves previas en verificación. La clave activa firma nuevos tokens, mientras que los tokens emitidos previamente se validan sin interrupción durante la ventana de gracia.
Seguridad y Audiencia Estricta Cada JWT emitido contiene el claim aud: [client_id]. Los SDKs y microservicios deben verificar que la audiencia coincida exactamente con el Client ID de la app para evitar la reutilización no autorizada de tokens entre distintos clientes.

Flujo OAuth 2.0 con PKCE & SSO

El flujo estándar recomendado para aplicaciones web (SPAs), móviles y backends es el Authorization Code Flow con PKCE (Proof Key for Code Exchange):

  1. Inicio de Autorización: La app cliente redirige al usuario a /oauth/authorize incluyendo client_id, redirect_uri, code_challenge (S256) y state.
  2. Sesión SSO o Autenticación: Peak Auth verifica si existe una sesión activa compartida (peak_session). Si no existe, muestra el portal de inicio de sesión con soporte MFA (TOTP / WebAuthn). Si la política de la aplicación exige MFA y el usuario aún no lo configuró, se le guía a completarlo.
  3. Redirección con Código: Peak Auth genera un código de autorización temporal de un solo uso (válido por 5 minutos) y redirige de vuelta a la app: https://tu-app.com/callback?code=...&state=....
  4. Intercambio de Token: El backend o cliente seguro intercambia el código en POST /oauth/token enviando el code_verifier original.
  5. Emisión de Tokens: Peak Auth responde con el Access Token firmado (RS256) y un Refresh Token rotativo.

SDKs Oficiales

Peak Auth provee librerías oficiales livianas con verificación offline, auto-descubrimiento JWKS con caching en memoria y middlewares listos para producción:

TypeScript / Node.js

Compatible con Express, Next.js y cualquier runtime Node.js / Bun moderno.

npm install @brunotarditi/peak-auth

Go (Golang)

Librería nativa con soporte para net/http y subpaquete para gin.

go get github.com/brunotarditi/peak-auth/sdk/go
